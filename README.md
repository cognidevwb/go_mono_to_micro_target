# go_mono_to_micro_target — the Go shop as five services (target)

This is the target side of a Go monolith-to-microservices modernization. The
monolith is [`go_mono_to_micro_source`](https://github.com/cognidevwb/go_mono_to_micro_source):
one gin + gorm service on one Postgres database. Here the same shop is split into
five services behind a gateway, each with its own database, talking over HTTP and
NATS.

Everything in this repository was generated by the CogniDev Workbench playbook
**Decompose a Go monolith into microservices** (`modernization-go-monolith`), run
against the source repository. No code was edited by hand afterwards; the reports
and the documentation were added by running CogniDev's own tools on the result.

## What it is

| Service | Gateway prefix | Owns | Calls |
|---|---|---|---|
| `catalog-service` ([services/catalog](services/catalog/README.md)) | `/api/products` | Category, Product | — |
| `customers-service` ([services/customers](services/customers/README.md)) | `/api/customers` | Customer | — |
| `inventory-service` ([services/inventory](services/inventory/README.md)) | `/api/inventory` | StockItem | — |
| `payments-service` ([services/payments](services/payments/README.md)) | `/api/payments` | Payment | the payment provider |
| `orders-service` ([services/orders](services/orders/README.md)) | `/api/orders` | Order, OrderLine | catalog, customers, inventory, payments |

- **The one transaction became a saga.** In the monolith, placing an order read
  prices, checked the customer, reserved stock and charged payment inside a single
  `db.Transaction`. Here `orders-service` runs the `CreateOrder` saga: it reserves
  stock first, charges payment last, and creates the order in its own local
  transaction, which commits only once the charge succeeds. If a step fails, the stock already reserved is released through
  inventory's compensation route.
- **The in-process event bus became NATS JetStream** behind a transactional outbox:
  `order.placed` is published in the same commit as the order.
- **The package-level price cache** now lives only in `catalog-service`, with a
  30-second expiry so replicas converge.
- **The restock ticker** became a scheduled job that one replica runs under a
  database lease.

Go 1.26, gin, gorm, pgx, NATS; one Go module per service in a `go.work` workspace;
distroless non-root images; Docker Compose at the root, and Azure (`azd`) and
observability configuration under `deploy/`. The CI workflows are in `ci/github-workflows/`; move them to
`.github/workflows/` to run them.

## What's in `.cognidev/` and `docs/`

Open the repository in the CogniDev Workbench and the Understand tab loads these
without re-running anything.

- **`.cognidev/understand/`**: the structural map of the services: every file,
  symbol, call, route, entity and table, the data flow, and the categories each
  piece of code falls into. It also holds a guided tour (37 steps in 6 chapters)
  and 15 business use cases, such as "Place an order" and "Have a failed order
  release its reserved stock".
- **`.cognidev/go-classify/`**: every function, method and type sorted into 18
  categories of change (authentication, persistence, messaging, transactions and
  so on). A category a code fact proves is recorded with the fact. Where no fact
  settles it, Jev (TypeSafe System One, `jev-1.13.0`) was asked; answers that
  were not confident enough are listed for review rather than guessed. The
  readable version is [`CLASSIFICATION.md`](.cognidev/go-classify/CLASSIFICATION.md).
- **`docs/`**: the same map as a website. Open [`docs/index.html`](docs/index.html).
  It has the use cases, the guided tour, the architecture, the domains, the
  classes, the sequences, the API, the data model, the categories with a word
  cloud of the code's vocabulary, insights, and the file inventory.
- **`.cognidev/feature/`** and **`.cognidev/modernization-go-monolith/`**: the
  playbook's own record: the service map, the plan, every task, the gates and the
  scorecard.

## Build and run

```sh
make sync build vet test          # every module on its own
cp .env.example .env && docker compose up --build
```

The gateway listens on `:8080`. The monolith's original README is kept at
[docs/monolith/README.md](docs/monolith/README.md).
