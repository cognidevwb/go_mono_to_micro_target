# go_mono_to_micro_source — a Go monolith (source)

This is the source side of a Go monolith-to-microservices modernization: a small
online shop written as one gin + gorm service on Postgres. It's small enough to
read in an afternoon, but it has the same seams a real monolith has, so it shows
what a split has to deal with.

**Target:** the same shop split into five services behind a gateway is
[`go_mono_to_micro_target`](https://github.com/cognidevwb/go_mono_to_micro_target).

## What it is

| | |
|---|---|
| Language | Go 1.26, module `github.com/acme/shop` |
| Web and data | gin 1.12, gorm 1.31 with the Postgres driver |
| Code | 18 Go files, about 640 lines, in six packages under `internal/` |
| Business packages | `catalog`, `customers`, `inventory`, `orders`, `payments` |
| Shared plumbing | `platform`: the database, an in-process event bus, auth middleware |
| HTTP routes | 6: list and create products, register and get a customer, place an order, list my orders |
| Entities | 7: Category, Product, Customer, StockItem, Order, OrderLine, Payment |

These numbers come from CogniDev Understand run on this repository.

## Why it's a good source

- **One database for everything.** `platform.Open` migrates every model on one
  shared `*gorm.DB`. A split has to give each service its own tables.
- **One transaction across four packages.** `orders.Service.PlaceOrder` reads
  prices from catalog, checks the customer, reserves stock and charges payment
  inside a single `db.Transaction`. Across services that has to become a saga
  with a way to undo each step.
- **Coupling the compiler won't warn you about:**
  - `catalog.priceCache` is a package-level map behind a `sync.RWMutex`;
  - `platform.Bus` is an in-process event bus: orders publishes
    `order.placed` and inventory listens;
  - `platform.UserIDKey` is a request value the auth middleware sets and
    orders reads;
  - `payments.Gateway` makes an outbound HTTP call to a payment provider;
  - `inventory.StartRestockJob` is a background ticker goroutine.
- **Two deliberate legacy bugs.** `inventory.Service.Reserve` reads, checks and
  then writes, so two orders can oversell. `payments.Payment.Status` is a bare
  string.

## Build and run

```sh
go mod tidy && go build ./...
DATABASE_URL=postgres://localhost/shop?sslmode=disable \
  PAYMENTS_URL=http://localhost:9090 go run ./cmd/shop
```
